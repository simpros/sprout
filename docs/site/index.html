sprout

Per-PR preview databases for self-hosted deploys

Every pull request gets an isolated Postgres database on a shared instance — plus an optional preview app behind Traefik. CI drives the lifecycle with the sprout CLI; no forge webhooks.

How it works

An operator deploys Postgres + the sprout gateway + Traefik once. An adopting repo adds .sprout.yaml and calls the CLI from CI.

create → migrate (app) → seed (optional) → hand over → drop PR opened / synchronize PR closed │ │ ▼ ▼ sprout deploy ──────────────────► sprout teardown │ │ ├─ CREATE DATABASE ├─ stop app / seed / services │ sprout_<slug>_pr<id> └─ DROP DATABASE ├─ start app container │ + Traefik Host labels └─ optional seed image (after health check) │ ▼ https://pr-{id}.your.app

1. Create

Gateway creates a logical DB on the shared Postgres instance.

2. Migrate

Your app image waits for Postgres, runs migrations, then starts.

3. Seed

Optional one-shot seed image runs after the app health check passes.

4. Hand over

Preview URL is live. Synchronize re-deploys keep the same DB.

5. Drop

On PR close, CI calls teardown. Sweep cleans up if CI missed it.

Quickstart

Operator — deploy the gateway once

# from the sprout repo
cp compose.env.example compose.env
# edit POSTGRES_PASSWORD, SPROUT_PREVIEW_POSTGRES_URL, SPROUT_PG_PASSWORD

docker compose --env-file compose.env up -d --build
curl -sf http://127.0.0.1:7331/healthz

Full operator guide: docs/deploy.md.

Adopter — wire your repo

# .sprout.yaml
slug: myapp
preview:
  hostname: "pr-{pr_id}.myapp.preview.example.com"
# CI (GitHub Actions) — secrets: SPROUT_URL, SPROUT_TOKEN
# Install CLI from a release asset, then:
sprout deploy -i "$APP_IMAGE"          # optional: -s "$SEED_IMAGE"
sprout teardown                        # on pull_request closed

Copy-paste starter: examples/adopting-repo/. Full adopter guide: docs/adoption.md. GitLab: use the published preview component (#127).

CLI reference

Install a release binary (glibc: sprout-linux-x64; Alpine: sprout-linux-x64-musl) or run from this monorepo via bun run --cwd apps/cli. Auth: set SPROUT_URL and SPROUT_TOKEN (except health).

CommandPurpose
sprout deploy -i <image> [-s <seed>] Create or synchronize a preview (DB + app; optional seed / services).
sprout teardown Remove the current PR’s preview (idempotent).
sprout drop <pr_id> [--yes] Operator drop of a specific PR preview (confirmation unless --yes).
sprout list List registered previews (JSON).
sprout health Hit gateway /healthz (no token).
sprout doctor Gateway self-check (networks, Postgres, forge, drift).
sprout logs <pr_id> Fetch preview container logs for debugging.
sprout admin token … Create / list / revoke deploy tokens (admin token required).
sprout ci <preview|teardown|reseed|logs> CI helper: build/push/deploy, teardown, reseed, or logs from CI env.
sprout worktree-db <provision|drop> Local per-worktree Postgres DB (no gateway).

Identity (repo + PR id) is inferred from CI env or git remote; override with --repo where supported. Full flags per command: sprout <command> --help; CI details: docs/adoption.md.

Adopting-repo config reference

Root file: .sprout.yaml. Unknown keys are rejected.

KeyRequiredNotes
slug yes Short alphanumeric name used in DB and container names.
preview.hostname yes Host template; {pr_id} substituted at deploy time.
preview.env no Remap connection env injection names (see ADR 0007).
preview.app_env no Extra app env; supports {hostname}, {pr_id}, {commit_sha}, generate, required.
preview.services no Companion containers (workers, secondary APIs).
health for seed path, interval, timeout, expect — required when seeding.
build no dockerfile for sprout ci preview (default Dockerfile).
seed no Seed dockerfile / env / args; enables seed build+deploy in CI helper.

The gateway injects connection env into app/seed containers by default as PGHOST, PGPORT, PGUSER, PGPASSWORD, PGDATABASE (names remappable via preview.env). Details: docs/adoption.md.

Operator deploy reference

Reference stack: docker-compose.yml — Postgres, gateway, Traefik. The gateway mounts the Docker socket and joins both the Traefik and Postgres networks.

  • Local smoke: docker compose --env-file compose.env up -d --build
  • Health: GET /healthz on the gateway host port (default 7331)
  • Bootstrap admin token: see deploy.md
  • Registry pull: configure gateway registry auths; image host comes from the deploy image ref
  • Sweep: periodic reconcile of previews vs Postgres, containers, and open PRs

Full env table and Coolify / Traefik notes: docs/deploy.md.

FAQ

Does sprout replace my PaaS?

No. It provisions per-PR databases and optional preview containers next to your existing Traefik (including Coolify-managed). CI still builds and pushes images.

Do I need forge webhooks?

No. Symmetric CI on PR open / synchronize / close drives deploy and teardown (ADR 0004). Sweep recovers if teardown is missed.

Where does seed data come from?

From a user-built one-shot seed image (ADR 0003). The gateway does not clone your repo.

Can two PRs share a database?

No. Each PR gets sprout_<slug>_pr<id> on the shared instance. Synchronize re-deploys keep that same database.

GitHub and GitLab?

Yes. GitHub Actions example in examples/adopting-repo/. GitLab: published preview CI component (issue #127).
